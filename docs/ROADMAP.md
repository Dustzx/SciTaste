# SciTaste 路线图

本页只维护方向、依赖和退出条件，不记录每日运行流水。项目当前工作以原生 `submission_plan` 为准。此前阶段记录和完整退出条件保存在[原路线图快照](archive/snapshots/ROADMAP.pre-20261012.md)，历史完成状态不会因本次整理重新认证。

## 当前方向

统一使用 SciTaste 名称。优先完善 Idea Research & Discovery，并保留 Experiment、Writing、Figure、Review 的全流程定位。Scientific Taste 的表示、选择性参与决策、跨阶段迁移与有限预算下的实际收益，是需要验证的研究问题。

检索和界面是能力基础；工程覆盖、案例数量和稿件数量不能替代科学证据。

## 工作流与退出条件

| 工作流 | 实现基础 | 仍需交付的验收证据 |
| --- | --- | --- |
| Idea Research & Discovery | 检索、来源组织、问题构造和迭代接口 | 来源可追溯、研究空白成立、构造效率与 idea 质量的匹配比较 |
| Shared Scientific Taste | 候选、审核、部分准入、检索及决策留痕 | 任务相关经验冻结、适用边界、实际采用证据与匹配 Taste 效果 |
| Experiment 与赛马 | 原生执行、预算、对照和投稿计划 | 真实强方法比较、独立任务、未曝光确认、机制消融、失败与全成本 |
| Writing / Figure / Review | 证据绑定稿件、图表、建议和评审闭环 | 真实证据缺口解决、限定范围的表达/判断质量评价；不能仅靠润色提升论文主张 |
| 产品与跨阶段集成 | 原生 runtime、workspace、共享经验与投稿视图 | 已维护的经验确实作用于具体决策点，并能回溯采用、弃权、效果与回退 |

## 科学交付的依赖顺序

1. `task-freeze`：真实研究任务、独立单位、划分、来源与评价终点。
2. `taste-freeze` / `method-freeze`：按项目实际工作 ID 冻结经验或方法、原模型与强控制、资源、停止/扩展门。
3. `primary-experiments`：就绪的独立批次及时执行，按同信息/总预算比较；准备工作不抵扣主实验。
4. `mechanism-and-transfer`：排除替代解释，做机制归因、独立来源与未曝光确认。
5. `paper-structure` 与交付：结果随产随写，完善失败、成本、边界、稿件与审阅；最终以具体项目完整科学门为准。

这些 ID 是现有项目使用的交付类型，不构成一份新的平行调度计划。不因日历到点、单个 run 完成或文档整理就关闭里程碑；具体项目允许已就绪的独立批次并行。

## 自下而上迭代入口

按[经验接入规范](taste/EXPERIENCE_INTEGRATION.md)，从有结果的决策和反例提炼候选经验；分别进入 Taste、程序规则或稳定 skill。优先打通 Writing 与赛马的实际消费记录，再以未参与提炼的任务验证迁移，避免只扩大经验池。

## 维护方式

- 当前任务、数值、预算和下一实验写回原项目，不追加在本页。
- 通用能力变更更新对应模块文档；本页仅在方向或退出条件改变时修改。
- 会议日期以版本化场所目录及具体项目计划为准，旧十天计划和会议名称不作为当前调度依据。
- 文献和冻结合同见[研究资料](research/README.md)与[评测入口](evaluation/README.md)；以前的阶段流水见[历史档案](archive/README.md)。
