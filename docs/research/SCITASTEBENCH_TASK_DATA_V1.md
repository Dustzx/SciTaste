## Scientific and leakage boundaries

Concrete groups are connected components under maximum per-ingredient difference
0.5 kg/m³, excluding target and age. No component spans train, validation and test.
This is not proof of separate labs, batches or material families. The primary
estimand gives each recipe equal weight: per-recipe MAE, averaged over recipes, MPa.
Row MAE and RMSE remain secondary. Threshold sensitivity and model/representation
controls can use public data only. A random-row score is not the primary endpoint.

Bike forecasts each following day's observed hours using a frozen fit and calendar
features only. The day-before 23:00 origin gives horizons 1–24 hours; no online label
updates or refits. Training ends June 2012, validation is July–September, evaluator
test October–December. There are no actual future-weather predictors, count components,
daily totals or row-index predictor. Missing hours are not zero-filled. The primary
endpoint averages per-date MAE in rentals/hour. The task does **not** identify weather
causality or validate cross-city transfer; the calendar-only narrowing is deliberate.

Both tasks permit different hypotheses and a defensible negative finding. Both
require executed experiments, reproducible code, a paper, four fixed scientific
conclusion slots, and review/revision or evidence-backed stopping. Empty claims
cannot receive perfect groundedness. Endpoint performance, claim support, paper
quality and review response remain separate—not one mixed-domain composite score.

Each dataset is one lineage. Public sources can be reconstructed or memorized;
`private/` is an access boundary, not proof of secret/uncontaminated observations.
Researcher processes must not mount raw sources/private assets or retrieve source
labels. The export function copies only frozen allowlisted public files, but it is
not itself process/network sandbox enforcement. No formal assignment has been made.

## Executable data interface

- `scripts.build_full_task_data`: bounded official acquisition, deterministic data
  construction, actual published reference CLI runs, source and environment receipts.
- `scripts.scitastebench_task_data export`: integrity-bound researcher-only assets.
- `... score`: exact row coverage and finite-value enforcement; fixed private endpoint.
- `... review-evidence`: group and predefined slice observations from public validation
  only. It does not read private labels, scores, or invent a reviewer conclusion.
- `benchmark.full_task_data.summarize_claim_judgments`: fixes the claim denominator,
  preserves insufficient/contradicted judgments, and labels uncalibrated AI judgments.

The reference is a fixed ExtraTrees regressor, not an AutoResearch method baseline.
Its published CLI was actually executed once per task (about 1.32 and 1.72 seconds
including Python startup). No optimization search, model API or GPU was used. Scorer
receipts are evaluator-private. This establishes reference executability, not independent
reproduction by another team or full scientific success. Reference code and versions
are bound in the pack; later code fixes do not rewrite that frozen snapshot.

The experimental modes are not confused with controller training. These two reference
runs are **training-based CPU fits**. The public protocol permits training-free
solutions, but none has yet established training-free coverage. Remote-GPU research
